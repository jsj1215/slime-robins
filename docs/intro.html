💡 왜 만들었나

아이스크림 가게 콘셉트에 기술 실험을 하나 얹었어요

"31가지 맛을 고르는 아이스크림 가게"라는 익숙한 틀을 빌려, 슬라임 31종을 고르고 바로 만져보는 웹 장난감을 만들었습니다. 진짜 목표는 그 안쪽에 있어요. 녹음 파일 없이 브라우저 API만으로 손에 붙는 감촉과 소리를 얼마나 그럴듯하게 낼 수 있는지 확인해보고 싶었습니다.

01
소리가 먼저, 물리는 그다음

ASMR 슬라임 영상의 재미는 대부분 소리에서 나옵니다. 그래서 제스처가 들어오면 사운드가 즉시 반응하는 것을 1순위로, 슬라임이 퍼지고 늘어나는 모양을 2순위로 잡았어요.

02
샘플 파일 없는 절차적 합성

드래그 속도와 압력이 바뀔 때마다 필터와 볼륨이 따라 움직여야 해서, 고정된 mp3 재생 대신 Web Audio 노드 그래프로 소리를 매번 합성합니다.

03
백엔드 없는 순수 프론트엔드

로그인, 저장, 서버가 전혀 없습니다. 정적 파일만 올리면 모바일 터치와 데스크탑 마우스 양쪽에서 똑같이 동작하도록 만드는 것이 범위였어요.

👆 5가지 제스처

손가락 하나로 모든 감촉과 소리를 만들어요

✋
드래그
Drag

안쪽을 누른 채 10px 넘게 움직이면 드래그. 끈적한 노이즈가 이어지고, 빠르게 끌수록 필터가 열리고 음높이가 올라가 소리가 밝아집니다.

👇
누름
Press

슬라임 안쪽을 220ms 넘게 꾹 누르고 있으면 움직이지 않아도 묵직한 "퉁" 소리 뒤로 낮은 노이즈가 이어집니다. 펜이나 압력 감지 기기에선 누르는 세기가 볼륨에 반영돼요.

🤏
늘리기
Stretch

가장자리(반지름 65% 바깥)를 잡고 끌면 늘리기. 멀리 당길수록 필터가 올라가 소리가 얇아지고, 손을 떼는 순간 짧은 "톡" 소리가 납니다.

👆
탭
Tap

220ms 안에 누르고 떼면 탭. 짧은 타격음과 함께 두드린 곳에서 물결이 퍼지고, 슬라임의 노이즈 성향에 따라 음색이 달라집니다.

🤲
흔들기
Shake

0.6초 안에 좌우로 세 번 방향을 바꾸면 흔들기. 떨리는 소리와 함께 슬라임이 출렁이고, 색 덩어리가 슬라임 속에 섞여 남습니다.

🍦 6가지 플레이버 그룹

슬라임의 물성과 사운드를 카테고리로 나눈 슬라임 라빈스만의 분류 체계

🍯
쫀득관
6종 보유

점도가 높아(0.8) 손을 천천히 따라오는 슬라임. 60~140Hz 저음 사인파에 브라운·핑크 노이즈를 섞어 끈적하고 묵직한 소리를 냅니다.

⚡
탱탱관
6종 보유

점도가 낮아(0.2) 손끝을 빠르게 따라옵니다. 245~356Hz 사각파 위주라 통통 튀는 또렷한 소리가 나요.

💧
물컹관
6종 보유

낮은 점도의 물기 많은 슬라임. 중력값이 가장 커서(0.3~0.4) 가만히 두면 아래로 처지고, 공명이 큰 고음 필터(Q 3~9)로 물방울 같은 소리를 냅니다.

🍿
바삭관
6종 보유

팝콘, 초코칩, 얼음 크리스탈, 진주알 같은 토핑이 처음부터 섞여 있는 크런치 슬라임. 노이즈 비중(0.45~0.9)이 높아 화이트·핑크 노이즈 쪽의 바삭한 소리가 납니다.

☁️
부드러움관
6종 보유

구름처럼 가벼운 슬라임. 삼각파 위주에 핑크 노이즈를 섞고 필터를 400~600Hz로 낮게 잡아 볼륨도 가장 작고 포근한 소리를 냅니다.

🌈
스페셜관
1종 보유

31번째 한정 슬라임 "레인보우카오스". 제어점이 24개로 가장 많고, 무지개색 별 토핑이 섞여 있으며 톱니파로 거친 소리를 냅니다.

🧠 핵심 설계 결정

무엇을 골랐고, 왜 골랐고, 무엇을 포기했는지

물리
잡을 땐 위치 추종, 놓으면 스프링
결정
잡은 지점에서 가까운 제어점일수록 손가락 이동량을 많이 받도록 smoothstep에 거리 가중을 한 번 더 곱한 감쇠 커널로 목표 위치를 정하고, 매 스텝 그 위치로 일정 비율씩 다가가게 했습니다. 멀리 당길수록 커널 반경이 최소 35%까지 줄어듭니다.
이유
힘을 적분하는 스프링 모델은 강성 값에 따라 쉽게 튀거나 폭주합니다. 위치를 직접 보간하면 항상 안정적이고, 반경이 줄어드는 덕분에 슬라임 특유의 "가늘고 긴 목"이 자연스럽게 나옵니다. 손을 떼면 현재 모양을 새 기준 모양으로 삼아 늘어난 채로 남아요.
트레이드오프
손을 놓은 뒤에는 탭과 흔들기가 넣은 힘을 속도로 적분하고, restoreStrength로 정한 스프링이 출렁임을 휴지 모양으로 가라앉힙니다. 속도와 변위에 상한을 둬 폭주하지 않아요. 대신 늘린 모양 자체를 둥글게 되돌리는 탄성은 없습니다. 중력 처짐도 반지름의 15%까지만 쌓여 오래 두어도 화면 밖으로 흘러내리지 않습니다.
src/hooks/useSlimeEngine.ts · src/engine/RadialMesh.ts · src/engine/physics.ts
루프
고정 타임스텝 + 누적기 클램프 + 보간
결정
물리는 항상 1/60초 단위로만 진행하고, 남은 시간 비율(alpha)로 이전 위치와 현재 위치를 보간해서 그립니다. 누적 시간은 최대 4스텝 분량으로 자릅니다.
이유
주사율이 60Hz든 120Hz든 같은 결과가 나오고, 탭을 오래 비웠다 돌아왔을 때 밀린 스텝을 한꺼번에 돌리다 멈추는 상황(spiral of death)을 막습니다.
트레이드오프
스텝을 버리는 순간에는 시뮬레이션 시간이 실제 시간보다 느리게 흐릅니다. 장난감 성격상 정확한 시간보다 끊김 없는 쪽을 택했어요.
src/engine/SimulationLoop.ts
사운드
녹음 파일 없이 노이즈 + 필터로 합성
결정
슬라임의 noiseAmount 값으로 브라운 / 핑크 / 화이트 노이즈 중 하나를 고르고, 오실레이터와 함께 lowpass 필터에 통과시킵니다. 필터 컷오프에는 느린 LFO를 걸어 소리가 살아 움직이게 했습니다.
이유
드래그 속도에 따라 필터가 열리고, 압력에 따라 볼륨이 바뀌는 식으로 매 순간 파라미터를 바꿔야 해서 mp3 재생으로는 표현이 어렵습니다. 31종 모두 숫자 몇 개만 바꿔 다른 소리를 낼 수 있어요.
트레이드오프
실제 녹음만큼 사실적이진 않습니다. 2~3초짜리 노이즈 버퍼는 색깔당 한 번만 만들어 캐시하고, 제스처마다 가벼운 버퍼 소스만 새로 만들어요.
src/sound/SlimeSoundBank.ts
사운드
싱글톤 AudioContext와 "딸깍" 없는 엔벨로프
결정
AudioContext는 앱 전체에 하나만 두고, pointerdown마다 멈춰 있으면 다시 resume 합니다. 소리는 0에서 attackTime 동안 올리고, 끌 때는 setTargetAtTime으로 줄인 뒤 releaseTime이 지나면 노드를 멈추고 연결을 끊습니다. Web Audio를 쓸 수 없으면 소리만 빠지고 물리는 그대로 동작해요.
이유
iOS Safari 같은 브라우저는 사용자 제스처 없이 오디오를 시작하지 못하고, 백그라운드에 다녀오면 컨텍스트가 다시 멈추기도 합니다. 게인을 갑자기 0이나 최대로 바꾸면 파형이 끊겨 클릭 노이즈가 생기기 때문에 항상 부드럽게 바꿉니다.
트레이드오프
첫 터치 전에는 소리가 나지 않고, 멈춘 뒤에도 잠깐 꼬리가 남습니다.
src/sound/AudioEngine.ts
제스처
누른 위치와 움직임으로 의도를 나누는 상태 머신
결정
현재 슬라임 무게중심 기준으로 반지름 65% 바깥을 잡으면 늘리기, 안쪽이면 누름 후보로 시작합니다. 10px 넘게 움직이면 드래그, 220ms 안에 떼면 탭, 220ms 넘게 누르고 있으면 누름, 0.6초 안에 좌우 방향이 실제로 세 번 뒤집히면 흔들기로 판정해요. 누름에서 드래그로 넘어가면 소리도 바뀝니다.
이유
손가락 하나로 다섯 가지 동작을 구분해야 해서, 멀티터치나 기기 센서 없이 위치, 거리, 시간, 방향 전환만으로 판정 규칙을 만들었습니다.
트레이드오프
처음 닿은 포인터 하나에만 고정하고 다른 손가락은 무시하므로 두 손가락 동작은 지원하지 않습니다. 기기를 실제로 흔드는 DeviceMotion 입력도 없어요.
src/gesture/GestureRecognizer.ts · src/gesture/PointerTracker.ts
구조
프레임 데이터는 React 바깥에
결정
메시 좌표와 속도, 포인터 상태, 진행 중인 제스처는 모두 useEffect 클로저 안의 plain 객체에 둡니다. React state는 화면 전환에만 씁니다.
이유
초당 60번 바뀌는 값을 state에 넣으면 매 프레임 리렌더가 일어납니다. 캔버스는 React가 그릴 필요가 없으니 엔진이 직접 그리게 했어요.
트레이드오프
엔진 상태를 React DevTools로 볼 수 없고, 정리(cleanup)를 직접 빠짐없이 챙겨야 합니다.
src/hooks/useSlimeEngine.ts · src/App.tsx
데이터
5개 아키타입 + 31개 델타
결정
쫀득 / 탱탱 / 물컹 / 바삭 / 부드러움 아키타입이 물리, 사운드, 비주얼 기본값을 모두 갖고, 각 슬라임은 다른 필드만 적습니다. resolveSlime()이 둘을 합칩니다.
이유
31종을 하나하나 튜닝하는 대신 아키타입 5개를 먼저 맞추고 나머지는 조금씩만 바꾸면 됩니다. 슬라임 추가도 객체 한 줄이면 끝나요.
트레이드오프
얕은 병합이라 중첩 필드를 부분적으로 덮어쓸 수 없습니다. pitchRange 같은 배열 필드는 통째로 덮어써요.

⚡ 성능 고려

모바일에서도 버벅이지 않도록 코드에 들어간 장치들

🧂
토핑 마크는 최대 200개

흔들기, 스페이스바, 8~25초마다 오는 랜덤 이벤트로 토핑이 계속 쌓여도 가장 오래된 것부터 버려 200개를 넘지 않습니다. 매 프레임 클립 영역 안에 그리는 양에 상한을 둔 거예요.

🎲
시드 기반 난수 + 캐시

표면 질감 점은 슬라임 id로 시드를 준 의사난수로 한 번만 만들고 Map에 캐시합니다. 매 프레임 새로 계산하지 않고, 같은 슬라임은 언제 열어도 같은 무늬가 나와요.

🖥️
DPR 최대 2배와 ResizeObserver

캔버스 버퍼를 DPR 배수로 잡되 2배로 제한해 DPR 3 기기에서 픽셀 수가 9배로 늘지 않게 했습니다. 리사이즈마다 DPR을 다시 읽고, 메시를 새 중심으로 옮겨요.

🧹
언마운트 시 전부 정리

메뉴로 돌아가면 rAF 루프, 랜덤 이벤트 타이머, 키보드와 포인터 리스너, ResizeObserver, 재생 중인 소리를 모두 멈춥니다. 슬라임을 여러 번 바꿔도 루프가 겹쳐 돌지 않아요.

📉
경로와 색은 한 번만 계산

외곽선은 프레임마다 한 번 정렬해 Path2D로 만들고 클리핑, 채우기, 테두리에서 같이 씁니다. 슬라임 색 섞기는 렌더러를 만들 때 한 번만, 노이즈 버퍼는 색깔당 한 번만 만들어요.

🐢
기기 성능별 메시 단계 조정 계획

아직 없습니다. 제어점 수는 슬라임 데이터(16~24개)로 고정이에요.
